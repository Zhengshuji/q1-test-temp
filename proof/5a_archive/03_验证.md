# 验证：$(5a)$ 的等价形式、阈值与最小增广

## 1. 本归档的独立检查

```bash
python proof/5a_archive/scripts/verify_5a.py
```

输出（2026-10-21 实测）：

```
实例数：12；p1 最小增广检查：12
随机 L 样本：(5a) 成立 22，不成立 26
三种形式一致；p1 的 q0=sum(eta) 与 (5a) 均通过 ✓
```

脚本检查三件事：

1. **三种等价形式**：4 块秩形式 `rank[LA;L;CA;C]=rank[L;CA;C]`、行包含 `condA`、核条件
   `ker[L;CA;C] ⊆ ker(LA)`，在 12 个随机实例 × 4 种行数（$k=0,1,2,3$）上逐一对比，全部一致；
2. **ground check**：随机 $L$ 中 $(5a)$ 成立 22 个、不成立 26 个——两侧都有点，不是“两边都 False”的空检验；
3. **p1 的最小增广**：`rows(Lx)=q0=sum(eta)`，且 $L_x$ 满足 $(5a)$（三种形式都通过）。

> 说明：这一步只验证 `p1` 的**构造**与 $q_0$ 的行数；$q_0$ 的**下界**（最小性）来自 P1 Theorem 2，
> 不是这个脚本能验证的（见 §4 保留）。

## 4. 保留与局限

1. **$q_0=\sum\eta_j$ 只有 P1 Theorem 2 一个来源**。项目没有独立证明其下界；
   `verify_5a.py` 只验证 `p1` 的构造与行数，不验证最小性。FINAL 明确把这条列为
   “全项目阈值的核心，却只有一个来源”。
2. **T3/T4 未 Lean 形式化**。阈值与满测度的证明在 [proof/A](../../archive/proof_notes_dimV_line/A_分支A的完整证明.md)；
   Lean 目前覆盖的是 $(5a)\iff$ 分解 $\iff$ 核条件这一链，不是阈值。
3. **数值检查是回归，不是证明**。三种等价形式已有 Lean 证明；脚本的作用是防止实现/口径回归。
4. **库的 `solve` 有已知缺陷**（零空间基不满足残差）。本归档的 `verify_5a.py` 只用
   `rk`/`mm`/`ker_basis`/`p1`/`condA`，不调用 `solve`；这与项目“关键判定用 `linalg_q`”的规范一致。
5. **q2/q3 的验证**不在本脚本里：q2 的论证是线代/拟阵（[q2.md](../../archive/problem_statements/q2.md)），
   q3 是端点情形（[q3.md](../../archive/problem_statements/q3.md)）。
