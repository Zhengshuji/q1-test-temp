## 0. 先看结论

| 你心里的问题 | 简短回答 |
|---|---|
| Lean 4 能证明我这条 NP-hard 吗？ | **理论上能，实践上不该**：要先形式化图灵机模型、多项式时间归约、NP 类，工作量远超数学部分。而且本命题按字面**缺少依据**（见 §0.1） |
| 那证明助手对我最大的用处是什么？ | **不是验证证明，而是验证命题本身**。(5a) 的闭式、`q₀ = Σηⱼ`、(A)/(S) 是否互相蕴含、量词顺序——这些都能被机器检查，而它们恰恰决定了"NP-hard"这句话是否站得住 |
| 最快、最便宜的验证是什么？ | **Python + sympy 脚本 + 小规模穷举 + 让同学来挑反例**。半天到两天。**本文正是用这个方法在 04 里找到了一个反例**（§7.3） |
| 形式化会不会替我把证明想出来？ | **不会**。它只检查你写的每一行是否合法。证明还是你自己想 |
| 有没有现成的轮子？ | **Isabelle/HOL + AFP** 是最接近"能写 NP-hard"的环境（已有 Cook–Levin 形式化与 Smith 标准形）。但它救不了"命题表述错了"这个问题 |

### 0.1 本文所依据的两处更正（务必先读）

| # | 第一稿以为 | 实际（已核实） |
|---|---|---|
| **E1** | (5a) 左端 3 块 `rank[LA; CA; C] = rank[CA; C; L]` | **(5a) 左端 4 块**：`rank[LA; L; CA; C] = rank[L; CA; C]`，这才是 P1 的条件 (A) ⇔ `row(LA) ⊆ row(L, C, CA)`。证据：`pdftotext -bbox` 坐标重建（`_extract/bbox_parse2.py`）+ P1 Corollary 1（`p1.txt:1147`）逐字一致 |
| **E2** | 由 (S) 可以推出 (A)（"λ=0 一行搞定"） | **两者互不蕴含**。本文用严格判据在 1500 个随机实例上实测：**S 成立而 (A) 失败 62 例，A 成立而 S 失败 250 例**（§1.1 案例 0、§4 层级 2 给出见证） |

**E2 的数学原因（值得记住）**：
在 3 块版本下，把 `(S)` 的 `∀λ` 实例化到 `λ = 0` 恰好得到 (5a)。
但在 **4 块**版本下，`λ = 0` 只给出 `rank[LA; CA; C] = h`，
而 (A) 要求的是更强的 `rank[LA; L; CA; C] = h`（即 `row(LA) ⊆ row(L, C, CA)`）。
两者之间差了一个 `L` 行块——**就是这多出来的一个行块让整个"一行证明"失效。**

> **这就是本文的主题**：手写证明最危险的错误不是算错，而是**在错误的命题表述上给出看起来正确的推理**。
> 而验证手段（无论机器还是人）的价值，首先在于**逼你说清你证的到底是哪句话**。

## 1. 为什么"证明"需要验证

### 1.1 本问题上最容易翻车的八类地方

下面每一条都对应本问题里**真实出现过或极易出现**的坑。**案例 0 是本文作者自己犯的错。**

#### 案例 0（真实发生）：在错误的 (5a) 版本上给出"只有一行"的证明

第一稿里写了这样的推理：

> "(S) 在 `λ = 0` 处给出 `rank[LA; CA; C] = rank[CA; C; L]`，**这正是 (5a)**。所以 `(S) ⇒ (A)` 是真的，而且证明只有一行。"

这段推理**每一步都合法**，但它证的命题是错的那个（3 块版本）。当 (5a) 更正为 4 块后：

- `λ = 0` 给出的是 `rank[LA; CA; C] = h`；
- (A) 要求的是 `rank[LA; L; CA; C] = h`；
- 由于 `rank[LA; CA; C] ≤ rank[LA; L; CA; C]`，前者是**更弱**的条件，推不出后者。

**机器检查验证结果**（n ∈ [2,4]，1500 个随机实例，严格判据）：

| 情况 | 例数 |
|---|---|
| (S) 成立 **且** (A) 成立 | 1175 |
| **(S) 成立但 (A) 失败** | **62** |
| **(A) 成立但 (S) 失败** | **250** |
| 两者都不成立 | 13 |

**见证（(S) 成立、(A) 失败）**：

```
A = [[-1,-2,-1, 1],
     [ 1, 0, 0, 0],
     [ 1, 2, 1, 0],
     [ 2,-2,-2, 1]]
C = [[-1, 1,-2, 1]]
L = [[ 2, 1, 0,-2]]
h = rank[L; CA; C] = 3
rank[λL - LA; CA; C] = 3   对所有 λ ∈ ℂ     →  (S) 成立
rank[LA; L; CA; C] = 4   >  3 = h           →  (A) 失败
```

**教训**：这个错误**不是计算错误**，而是"命题的读法"错误。任何数值脚本只要写成 4 块形式就能抓到它。
→ 所以**第 1 层验证（脚本）不是多余的形式主义，它是最便宜的错误探测器。**

#### 案例 1：量词顺序 `∃R ∀λ` vs `∀λ ∃R`

计划文档要求写的是：

- **正确**：`∃ R, (A)(R) ∧ ∀ λ ∈ ℂ, (S)(R, λ)`——先固定 `R`，再对所有 `λ`。
- **错误**：`∀ λ, ∃ R, ...`——这个命题**弱得多**，且在很多情形下平凡为真（`R` 可以随 `λ` 变）。

证明助手在这里的价值是决定性的：`∃R∀λ` 与 `∀λ∃R` 在 Lean 里是**字面上不同的类型**，写错就是证了另一个定理。

#### 案例 2：(S) 的右半平面版 vs 全平面版

- `∀λ ∈ ℂ` 可以用"最大子式的 gcd 是非零常数"来判定；
- `∀λ, ℜ(λ) ≥ 0` **不能**用 gcd 判据——`gcd ≠ 1` 只意味着"存在某个根"，那个根完全可能在左半平面。

这是本问题里最容易**把强版本和弱版本混为一谈**的地方。形式化时要定义成两个不同的命题（§6 的骨架里就是这么做的）。

#### 案例 3：只检查 (S) 的一个方向

`(S)`: `rank P(λ) = h` 对所有 `λ`。它等价于**两件事同时成立**：

- (i) 所有 `(h+1)×(h+1)` 子式恒等于 `0` ⇒ `rank P(λ) ≤ h` 处处成立；
- (ii) 所有 `h×h` 子式的 `gcd` 是非零常数 ⇒ `rank P(λ) ≥ h` 处处成立。

**只检查 (ii) 是错的**（本文第一版脚本就漏了 (i)）。实测影响：1500 个实例中有 **13 个** generic rank 超过 `h`——
这些实例会被"只查 (ii)"的脚本误判为 (S) 成立。**这是一个真实的、可复现的 bug。**

#### 案例 4：隐含前提 `rank[L₀; C] = p + r`

P1 §II 的全行秩假设。**这个前提在 04 的定理 2（闭式 `k = dim Z − dim V`）里没有写出来，而按字面它是假的。**
本文的对抗性验证找到了一个极小反例（§7.3），并确认：**加前提过滤后，闭式与穷举最优值 0 反例**
（附录 B 的 `--closedform`：138/138；另有一轮把候选池限制在 `Z` 内的更严格版本：369/369）；
**不加前提时会复现出反例**（400 例中 3 例）。

铁律：**每引用一条文献定理，就把它的前提抄下来，然后逐条检查你的构造是否满足。**

#### 案例 5：rank 不等式的方向

"秩相等"的证明几乎总要拆成两个方向。常见写法是先给便宜的上界（行空间包含 ⇒ 秩 ≤），然后在下一行当成 `=` 用。
形式化检查百分之百能抓到这类错误。

#### 案例 6：归约的方向与规模

NP-hard 要求从**已知 NP-hard 的问题**（Set Cover / Hitting Set）归约到本问题，而不是反过来。
还要说明构造规模是多项式的、矩阵元素是多项式长度的。手写时"方向反了"和"构造隐含指数规模"都很难被发现。

#### 案例 7：`rows(L)` 与 `rank L` 不是一回事

P3 用 **`rows(L)`（观测器阶数 = 行数）**；P1 用 **`ν_min = min rank ℒ`（秩）**。
若 `L` 的行线性相关，二者不等。**优化"行数"还是"秩"必须明确表态**（见附录 C）。

| 错误类型 | 具体例子 | 哪种验证手段能抓到 |
|---|---|---|
| **命题表述错** | 案例 0（3 块 vs 4 块）、案例 4（缺前提） | **小规模穷举 + 对抗审查**；证明助手（强制写清前件） |
| 量词顺序 | 案例 1 | 证明助手（强制写清）；人工审读清单 |
| 版本混淆 | 案例 2（ℂ vs 右半平面） | 人工审读；脚本里定义两个不同函数 |
| 检查不完整 | 案例 3（只查一个方向） | 交叉验证（两种独立算法结果比对） |
| rank 方向 | 案例 5 | **所有**层级；数值脚本最快 |
| **口径混淆（静默失效）** | 总行数 vs 额外行数（`q₀` vs `dim Z − dim V`）：脚本不报错，但"既没匹配也没反例" | 检查 `match` 计数**非零**；两种独立实现对照 |
| 归约反向/规模 | 案例 6 | 对抗审查；SAT 小实例双向检查；规模计数的算术证明 |
| 行数 vs 秩 | 案例 7 | 明确规格；穷举对照 |

### 1.2 什么是形式化验证

**形式化验证（formal verification）**：

> 把**命题**和它的**证明**都用严格定义的形式语言写下来，
> 交给一个很小的、被信任的**内核（kernel）**逐条检查：每一步是否由前面的步骤和少数几条公理合法推出。

关键点：

- 检查是**机械的**：内核不"理解"数学，只检查规则。它不会漏看、不会累、不会因为"这一步显然"就放过你。
- 被信任的东西极少：Lean 4 内核只有几千行，可以被人类通读（**de Bruijn 判据**：证明检查器应小到可被人类完全验证）。
- 结果是**二值的**，没有"大概对"。这正是它比同行评审强的地方。
- 代价：**你必须把一切说到机器能懂的程度**，通常比写给人看的证明长 5~50 倍。

类比：形式化验证相当于请一位**不懂数学、但极端严谨、记忆无限、永不疲倦的校对员**。
它不会告诉你结论对不对，只会告诉你"你从第 3 行走到第 7 行，这一步不合法"。

### 1.3 形式化验证 ≠ 自动证明

| | 自动定理证明器（ATP / SMT） | 证明助手（proof assistant） |
|---|---|---|
| 例子 | Z3, cvc5, Vampire, E | Lean 4, Coq/Rocq, Isabelle/HOL |
| 你给什么 | 一个命题 | 一个命题 **+ 一份证明草稿** |
| 它给什么 | sat / unsat / unknown | 检查通过 / 第 N 行不合法 |
| 自动程度 | 高（但难命题常 `unknown`） | 低（但**通过即正确**） |
| 对本题 | 只能处理很小的实例化子问题 | 能处理任意 `n` 的一般定理 |

**心智模型**：证明助手 = 一个编程语言 + 编译器，"程序"是证明，"类型"是命题（**Curry–Howard 对应**）。
编译通过 ⟹ 命题为真。**写证明就是写程序。**

所以：**形式化验证不替你想证明**。创造性工作（找引理、想构造、**把命题写对**）100% 还是你的。

### 1.4 形式化救不了你：陈述层面的错误

> **形式化保证的是"你的命题是真的"，而不是"你想要的命题被形式化了"。**

本问题上的陈述层面风险（结合 §0.1 的教训）：

1. **(5a) 的行块数**——案例 0。写成 3 块就会证出一个无关的定理。
2. **量词**——案例 1。
3. **`ℂ` 还是 `ℜ(s) ≥ 0`**——案例 2。
4. **"NP-hard"指的是哪个决策问题**——优化问题本身不在 NP 里，必须先定义**决策版**，证 NP-完全，再推出优化版 NP-hard。跳过这一步，"NP-hard"在形式上是不完整的。
5. **它到底是不是 NP-hard**——如果困难实际落在 ∃ℝ（§3.5），那么"NP-hard"这个**靶子本身就是错的**，形式化只会忠实地在此靶子上失败。

**结论**：形式化前后都要花时间在"我要证的到底是哪句话"上。这件事**没有任何工具能代替你**——
但**小规模穷举和对抗审查能廉价地帮你发现靶子错了**（案例 0 和案例 4 都是这样被抓到的）。

## 2. 证明助手（proof assistant）概览

### 2.0 术语小词典

| 术语 | 通俗解释 |
|---|---|
| **定理 / 引理（lemma）** | 都是"已证明的命题"。`lemma` 只是习惯上称呼辅助小结论；机器眼里没区别 |
| **策略（tactic）** | 一条改变当前待证目标的命令。如 `rw [h]`（重写）、`exact h`（"目标恰好是 h"） |
| **项（term）** | 证明本身也是"表达式"，可以像函数一样传递、组合 |
| **Mathlib** | Lean 4 的数学库，数千人协作的巨型开源项目 |
| **`sorry`** | 证明占位符。文件**仍能编译**，但会警告"这里有洞"。**绝不能出现在最终交付里** |
| **`axiom`（公理）** | 显式声明"我假设这条成立"。**可靠但条件性**：定理变成"在该假设下成立" |
| **内核（kernel）** | 真正做检查的那一小段代码 |
| **`#print axioms thm`** | 列出 `thm` 依赖了哪些公理。**审稿人该看的东西**：出现 `sorryAx` 就说明有洞 |
| **sledgehammer** | Isabelle 的"自动找证明"工具，很好用但不是万能 |
| **可判定（decidable）** | 命题若机器能**计算**出真假，就叫可判定。`∀ λ : ℂ, ...` 显然不是 |
| **`decide` / `native_decide`** | 对可判定的**有限**命题用计算直接判定真假 |
| **重写（rewrite）** | 用等式替换目标里的一段。几乎所有证明的主力动作 |

**给初学者的第一条实用建议**：遇到"这个引理叫什么"，别猜，用搜索：
`#check Matrix.rank`、`exact?`、`apply?`、`rw?`、`simp?`，以及社区搜索引擎
**Loogle**（按类型签名搜）和 **Moogle**（按自然语言搜）。

### 2.1 Lean 4 + Mathlib

#### 定位

- 当前**最活跃**的证明助手生态（Lean FRO 支持，Mathlib 贡献者数百人）。
- 语言本身就是实用的函数式编程语言。
- 编辑器体验好：VS Code + Lean 4 扩展有**目标状态面板**（实时显示当前要证什么、有哪些已知条件）——对初学者极其重要。
- 社区在 Zulip 上非常活跃，初学者提问通常几十分钟内有回复。

#### 数学库（Mathlib）现状

**与本题直接相关、已确认存在的部分**（我逐条核对了 Mathlib 文档）：

- `Matrix m n R`：矩阵类型，本质是 `m → n → R`。
- `Matrix.rank A`：定义为 `Module.finrank R A.mulVecLin.range`，返回 `ℕ`；需要 `[Fintype n] [CommSemiring R]`。
- **`Matrix.rank_eq_finrank_span_row` / `Matrix.rank_eq_finrank_span_cols`**：
  "秩 = 行张成空间的维数 / 列张成空间的维数"。**这一对引理是把 `rank` 和"行空间"连起来的关键。**
- `Matrix.rank_transpose`、`Matrix.rank_mul_le`、`Matrix.rank_mul_le_left/right`、
  `Matrix.rank_mul_eq_left_of_isUnit_det`、`Matrix.rank_of_det_ne_zero`、`Matrix.exists_rank_normal_form`、
  `Matrix.rank_add_rank_le_card_of_mul_eq_zero`、`Matrix.rank_le_width`。
- `Submodule R M`、`Submodule.span`、`Submodule.finrank_mono`（包含 ⇒ 维数 ≤）。
- `Polynomial R`、`EuclideanDomain.gcd`（`Polynomial ℂ` 是欧几里得整环）、`IsAlgClosed ℂ`。
- `Finset`、`Finset.card`、`Finset.sum`、`Nat.choose`：做计数的组合基础设施。

**不确定 / 需你自行检索确认**（不要相信我的记忆）：

- 块矩阵拼装 API `Matrix.fromBlocks` / `Matrix.fromRows` / `Matrix.fromCols` 的确切名字与用法。
- **`Matrix.SmithNormalForm`**（PID 上矩阵的 Smith 标准形）是否存在。若有，路径可能是
  `Mathlib/LinearAlgebra/Matrix/SmithNormalForm.lean`；**请在本地 Mathlib grep 确认**。
  若无，则"多项式矩阵的秩 / 子式 gcd"这套要自己搭。
- `Matrix.rank_neg`（`(-M).rank = M.rank`）是否存在。

#### 一个最小可跑的例子（演示"子空间包含"与"秩"）

```lean
import Mathlib.LinearAlgebra.Matrix.Rank
import Mathlib.LinearAlgebra.Dimension.Finrank

open Matrix

namespace Demo

/-- 行空间：由矩阵 `M` 的各行向量张成的子空间。
    `M i` 就是第 i 行（矩阵本质上是 `m → n → R` 的函数）。
    若你的 Mathlib 版本里 `Matrix.row` 可用，也可写 `Set.range M.row`。 -/
noncomputable def rowSpace {m n : Type*} [Fintype m] [Fintype n]
    (M : Matrix m n ℂ) : Submodule ℂ (n → ℂ) :=
  Submodule.span ℂ (Set.range fun i : m => M i)

/-- 例 1：秩的乘法不等式，Mathlib 一步到位。 -/
example {m n o : Type*} [Fintype m] [Fintype n] [Fintype o]
    (A : Matrix m n ℂ) (B : Matrix n o ℂ) :
    (A * B).rank ≤ A.rank :=
  Matrix.rank_mul_le_left A B

/-- 例 2（本题的核心模式）：**行空间包含 ⇒ 秩 ≤**。
    这就是把 (5a) 的"秩相等"翻译成"行空间互相包含"之后要用的那一步。 -/
example {m n : Type*} [Fintype m] [Fintype n]
    (M N : Matrix m n ℂ) (h : rowSpace M ≤ rowSpace N) :
    M.rank ≤ N.rank := by
  rw [Matrix.rank_eq_finrank_span_row, Matrix.rank_eq_finrank_span_row]
  exact Submodule.finrank_mono h

end Demo
```

**诚实标注**：上面是**带注释的示意代码**，不是逐字可编译的成品。
`rw [Matrix.rank_eq_finrank_span_row, ...]` 能否触发取决于该引理的确切语句形式。
若不生效：先 `#check Matrix.rank_eq_finrank_span_row` 看它的陈述，再改用
`simp [Matrix.rank_eq_finrank_span_row]` 或 `convert`。

### 2.2 Coq/Rocq + Mathematical Components (ssreflect)

#### 定位

- Coq（现名 Rocq）是 INRIA 系的老牌证明助手，工业界也在用（如 CompCert 编译器的验证）。
- **Mathematical Components（mathcomp）** 是它的数学库，源自四色定理、Feit–Thompson 定理等大型形式化项目。
- 风格特点：**ssreflect** 证明语言，核心是"**小规模反射**"——把命题转成可计算的布尔判定，用计算替代冗长推理。
  写法紧凑、适合"结构化"的有限组合与代数，但**习语难上手**。

#### 数学库

- **`mathcomp.algebra.mxalgebra`**：显式矩阵库。有 `\rank A`、`row_space` / `col_space`、
  `row_free` / `col_free`、`rank_leq_row` / `rank_leq_col` 等。
  **这是"显式矩阵 + 秩"最成熟的形式化库之一**（我核对了 mxalgebra 文档，`RowSpaceTheory` 一节确实存在）。
- `mathcomp.algebra.matrix`、`mathcomp.field.*`、`mathcomp.algebra.polynomial`。

**对本题的意义**：(5a)(5b) 的写法本来就是"把矩阵摞起来然后比秩"，与 `mxalgebra` 的风格**天然对齐**，
可能比 Lean 更顺手。

**局限**：

- mathcomp 以"显式矩阵 + 有限维"为主，**"多项式矩阵的秩 / Smith 标准形 / 子式 gcd"** 没有 Lean/Isabelle 那样的现成支持。
- 复杂度理论方面，Coq 侧**没有**像 Isabelle/AFP 的 Cook–Levin 那样成熟的 NP 基础设施。

#### 学习曲线

比 Lean 陡。ssreflect 的重写习语（`rewrite !lem`、`move=>`、`case:`、`elim/`）与主流证明助手很不一样。
好处是一旦上手，写"有限组合 + 显式矩阵"类证明非常快。

#### 与 Lean 的取舍

| 维度 | Lean 4 + Mathlib | Coq + mathcomp |
|---|---|---|
| 社区活跃度 | 最高 | 中等 |
| 矩阵秩基础设施 | 有 | **有且更"显式矩阵"** |
| 多项式矩阵 / Smith 形 | 不确定（需查） | 弱 |
| 复杂度理论 | 弱（推进中） | 弱 |
| 初学者友好度 | **较高**（目标状态面板 + 社区） | 较低 |
| 本题推荐度 | **首选**（入门与主线） | 备选（若团队已有 Coq 经验） |

### 2.3 Isabelle/HOL + AFP

#### 定位

- 德国慕尼黑工大 / 剑桥传统的证明助手，**自动化程度最高的通用证明助手之一**。
- 两大杀手锏：
  1. **sledgehammer**：把目标交给一堆外部 ATP（Vampire、E、Z3、cvc5…），找到证明后自动翻译回 Isabelle 脚本。
     初学者能靠它走很远。
  2. **AFP（Archive of Formal Proofs）**：条目化的高质量形式化库。
- 书写风格有 `apply` 脚本式与 **Isar**（接近人类数学写作的 `have`/`show`/`thus`）两种，后者可读性极好——
  对"想让导师/审稿人看懂"的场景是加分项。

#### 数学库（AFP 里与本题直接相关的条目）

我核实了以下 AFP 条目的存在：

- **`Rank_Nullity_Theorem`**（Divasón & Aransay）：秩–零化度定理。含 `rank`、`col-space`、`row-space`、`dim`。
  **这是"显式矩阵 + 行/列空间"最直接的现成形式化。**
- **`Jordan_Normal_Form`**（Thiemann & Yamada）：矩阵、`rank`、特征多项式、Jordan 标准形。维护良好。
- **`Smith_Normal_Form`**（Divasón & Thiemann，"A verified algorithm for computing the Smith normal form of a matrix"）：
  **PID 上矩阵的 Smith 标准形**。
  → 对本题意义重大：§1.1 案例 3 里"最大子式的 gcd"这条路线，**Isabelle 有现成的代数基础设施**，
  而 Lean/Mathlib 我**不确定**是否现成。
- **`Cook_Levin`**（见下）。

#### 关键优势：AFP 有 Cook–Levin 的形式化

这是**目前最接近"能直接写 NP-hard 归约"的形式化环境**：

- AFP 条目 **`Cook_Levin`** 里有 **`NP`** 理论文件，包含复杂度类 `P`、`NP`、多项式时间归约
  （以及诸如 `P_closed_reduction` 这样的引理）。
  也就是说：**"多项式时间归约"在 Isabelle 里不是要你从零定义的概念，而是一个已有的库概念。**

**但是必须诚实**：

- 即便如此，"从 Set Cover 归约到本问题"的完整链条仍然很重：要把本问题**编码成语言/判定问题**，
  写出归约函数，证明它是多项式时间的（用 AFP 的复杂度框架），再证明等价性。**这是一个真正的形式化项目。**
- Isabelle 本身的学习曲线也不低（Isar + 类型类 + 大量 locale）。
- **而且**：AFP 的复杂度框架**只覆盖 NP**。如果本问题的困难实际落在 ∃ℝ（§3.5），
  **现成的复杂度框架里根本没有那个类**，你连"陈述靶子"都做不到。

### 2.4 Mizar 与 Metamath（简述）

**Mizar**

- 起源于波兰，有独立期刊 *Formalized Mathematics*，作者把形式化证明当论文发表。
- **MML（Mizar Mathematical Library）** 很大，是历史上最成功的"形式化数学库"之一。
- 但**社区活跃度低、工具链老旧**、学习资料少。矩阵与秩相关结果在 MML 里有分布，但
  **我不确定是否存在"行空间/秩"的完整现代理论**——需自行查 MML。
- 结论：**对本问题不推荐。**

**Metamath**

- 极端极简：**几百行**的验证器 + 巨大的数据库（`set.mm` 等）。可信任基小到极致。
- 但数学覆盖以集合论、实分析、部分数论为主；**矩阵的秩、子空间、多项式代数、复杂度理论基本没有**。
- 结论：作为"最可信的基"是传奇级的；作为**本问题的工具**完全不适合。

**顺带一句**（知道名字即可）：`HOL Light`、`PVS`、`ACL2`、`Agda`/`Idris`。它们与本题的距离都不比上面几个更近。

## 3. 关键难点：形式化"NP-hard"本身

### 3.1 三张不同难度的"靶子"

修订后，本问题实际上有**三张不同性质的靶子**。它们的形式化难度**差别巨大**。
**先想清楚你要打哪一张，再决定用什么工具。**

| 靶子 | 命题 | 性质 | 形式化难度 |
|---|---|---|---|
| **T1** | 「(5a) 单独下，最小行数 = `dim Z − dim V`（等价于 `q₀ = Σηⱼ`），多项式可算」 | **纯数学定理**（有限维线性代数 + 组合计数） | ★★☆ **很适合形式化**。而且形式化它会**直接推翻**"仅 (5a) 就 NP-hard" |
| **T2** | 「(5a) ∧ (5b) 下判定 `ν_min = q₀` 是 NP-hard」 | **可疑**：涉及组合搜索 + **半代数可行性**，更像 ∃ℝ（§3.5） | ★★★★ 难，且**靶子本身可能错** |
| **T3** | 「把 `R` 限制在**给定候选族** `𝒞` 中时，判定 `k ≤ K` 是 NP-hard」（04 §3.4 的命题 𝒫′） | 组合优化，可由集合覆盖归约 | ★★★★★ 需要一个真实的复杂度理论形式化项目 |

**给初学者的关键建议**：
**你的形式化精力应该全部投在 T1 上。** 理由有三：

1. T1 是**纯线性代数**，正是 Mathlib 的强项（§2.5 第 1~7、12、13 行）。
2. T1 的形式化**有最高的认识论价值**：它把"仅 (5a) 是多项式可解的"这句话从"论文里的一段推理"
   变成"机器检查过的事实"，从而**彻底排除了把困难归因给 (5a) 的可能**。
3. T1 的每一部分（引理 1、定理 2 的上下界、`k^min = 0` 的刻画）都是**可独立验证的小单元**，
   失败成本低，适合作为学习 Lean 的练习。

### 3.2 一个 NP-hard 证明里到底有哪些对象

要**形式化**"问题 Q 是 NP-hard"，你的形式化环境里必须**先已经存在**：

1. **一个计算模型**：图灵机（单带/多带/非确定），或 RAM 模型——总之要有"什么算一次步骤"的精确定义。
2. **判定问题的编码**：Q 的一个实例必须能编码为字符串。否则"多项式时间"没有意义——时间是对**输入长度**而言的。
3. **多项式时间**：`∃ c, ∀ x, steps(f,x) ≤ |x|^c + c`，以及它的**封闭性**（复合仍是多项式时间）。
4. **多项式时间归约（Karp / many-one）**：`A ≤_p B` 的定义 + 传递性。
5. **复杂度类 NP**：存在非确定图灵机多项式时间接受，或等价地"存在多项式时间的证书验证器"。
6. **NP-hard / NP-完全**：`B 是 NP-hard ⟺ ∀ A ∈ NP, A ≤_p B`。

然后才是**你的数学**：构造归约函数 `φ`，证明 `x ∈ SetCover ⟺ φ(x) ∈ Q`（**双向**）、
`|φ(x)| ≤ poly(|x|)`、`φ` 在模型里可计算。

**成本分布**：第 1~6 项与你的线性代数问题**毫无关系**，而且是整个形式化里最重的部分。
你的数学（那个归约）可能只占 15% 的代码量。**这就是"不该在 Lean 里从零证 NP-hard"的全部理由。**

### 3.3 现状（诚实评估）

我核对了当前公开状态（请以你使用的版本为准，这些都在快速变化）：

**Lean 4 / Mathlib**

- ✅ 有 `Mathlib.Computability.TuringMachine.Computable`，含 **`Turing.TM2ComputableInPolyTime`**
  （TM2 模型下的多项式时间可计算性）。"多项式时间可计算"在 Lean 里**已经存在**。
- ⚠️ **复杂度类 `P`/`NP` 的完整基础设施仍在推进中**：Mathlib 仓库有相关 issue/PR
  （例如 issue #35366 "Step counting and complexity classes P/NP for TM1"）。
  **不要假设你 checkout 的 Mathlib 里已经有 `NP` 这个类**——请自己 grep / `#check` 确认。
- ❌ **没有**"NP-hard 归约"的现成库：没有 Karp 归约层的封装，没有 `NPComplete` 的通用定理集。

### 3.4 可行的折中路线：只形式化数学核心，把 Karp 1972 当假设

### 3.5 如果最终落到 ∃ℝ：那连"陈述靶子"都做不到

04 §3.3 已经指出：如果可行性完全由**连续参数 `Θ`** 决定，问题的复杂度类会落到
**∃ℝ**（存在性实数理论，介于 NP 与 PSPACE 之间），而**不是** NP-hard。

这在验证层面有一个非常重要、且常被忽略的后果：

> **今天没有任何一个证明助手提供 ∃ℝ 的形式化基础设施。**

- 要形式化"∃ℝ-hard"或者"∃ℝ-完全"，你首先得形式化**实闭域的一阶理论**
  （Tarski–Seidenberg / 量词消去）以及复杂度意义下的 ∃ℝ 类定义。
- 这比形式化 NP 还要难一个层级：NP 至少还有 AFP 的 `Cook_Levin` 可以站在肩膀上，
  而 ∃ℝ **我没有见到任何形式化实现**（这一条我标记为"需自行确认"，见附录 C）。
- 结论：**如果 T2 的靶子真的是 ∃ℝ，那么"用形式化验证这个结论"这条路目前是走不通的**，
  你只能退回到"人工证明 + 小实例实验"。而**发现这一点本身就是 T1 形式化的价值**：
  它把"困难不在 (5a)"这件事钉死了，从而迫使你把靶子改成 T3（候选族限制版），
  而 T3 才是有可能被形式化的 NP-hard 命题。

## 4. 实际可操作的验证层级（推荐给你的自查清单）

### 层级 1：数值 / 符号计算验证

**做什么**：用 Python（numpy + sympy）把 (5a)(5b)、闭式 `k = dim Z − dim V`、`q₀ = Σηⱼ` 写成脚本，
在**随机生成**的 `(A, C, L₀)` 上逐条检验。

**四个技术要点**（决定你的脚本是"有用"还是"自我欺骗"）：

**(1) (5a) 必须写成 4 块。** 这是案例 0 的直接教训：

```python
# 正确（4 块）
rank(vstack(L*A, L, C*A, C)) == rank(vstack(L, C*A, C))
# 错误（3 块，本文第一稿的 bug）
rank(vstack(L*A, C*A, C))    == rank(vstack(C*A, C, L))
```

**(2) 数值秩不能用来判 (5b)。** `np.linalg.matrix_rank` 用 SVD + 容差；当 `λ` 接近临界点时奇异值会连续穿过阈值，
你会得到**随机真假混合**的结果。所以：

- (5a) 用**精确算术**（`sympy.Matrix.rank()` 在有理数域上是精确的）；
- (5b) 必须用**符号方法**。

**(3) (5b) 的符号判据要检查两个方向**（案例 3 的教训）。
令 `h := rank[L; CA; C]`，`P(λ) := [λL − LA; CA; C]`。在 ℂ 上：

```
(S)  ⟺  ∀λ, rank P(λ) = h
     ⟺  (i)  所有 (h+1)×(h+1) 子式恒等于 0      （⇒ rank ≤ h 处处）
        ∧  (ii) 所有 h×h 子式的 gcd 是非零常数    （⇒ rank ≥ h 处处）
```

**只检查 (ii) 是错的。** 我在 1500 个随机实例中发现 **13 个** generic rank 超过 `h`——
它们会被"只查 (ii)"的脚本误判为 (S) 成立。

**(4) 用实测算术检验 (S) 与 (A) 的关系。** 这正是案例 0 被发现的途径：

| 实验 | 结果（n ∈ [2,4]，1500 随机实例） |
|---|---|
| (S) 成立 ∧ (A) 成立 | 1175 |
| **(S) 成立 ∧ (A) 失败** | **62** |
| **(A) 成立 ∧ (S) 失败** | **250** |
| 都不成立 | 13 |
| generic rank P > h（若不查 (i) 会误判） | 13 |

可运行代码见 **[附录 B](#附录-b可运行的-python-验证脚本)**（我在写本文时实际跑过，数字即上表）。

**(5) 如果你要的是 `ℜ(s) ≥ 0` 版本**，**gcd ≠ 1 不等于失败**（根可能全在左半平面）。
正确做法：先算 `g(λ) = gcd(...)`，再判断 `g` 是否有 `ℜ(λ) ≥ 0` 的根
（高精度数值求根，或 Routh–Hurwitz / Sturm 计数）。**务必在代码注释里写清你验的是哪个版本。**

| | |
|---|---|
| **能发现的错误** | 命题表述错（案例 0、案例 4）；rank 方向写反；`(A)`/`(S)` 蕴含关系搞错；检查不完整（案例 3）；维度接错（形状不匹配会直接抛异常）；`q₀ = Σηⱼ` 与闭式对不上 |

### 层级 2：小规模穷举反例搜索

**做什么**：在 `n ≤ 6` 的玩具规模上**穷举**：

1. 穷举候选增广行的**所有子集**，找满足 `(A) ∧ (S)` 的最小行数；
2. 与理论预测比较：是否等于 `dim Z − dim V`（或 `q₀ − r`）；
3. 检查"达到 `q₀` 的最小增广**不唯一**"，且存在某个达到 `q₀`、满足 `(A)` 但**违反 `(S)`** 的增广
   （这是 `ν_min ≥ q₀` 的"燃料"）。

```python
def min_extra_rows(A, C, L0, pool, maxk):
    """在候选池 pool 里穷举所有大小 <= maxk 的子集，返回最小**额外**行数。
       注意：q0 是**总**行数，所以正确的对照是  L0.rows + k  ==  q0。
       这是指数时间；只能用于玩具规模。"""
    for k in range(maxk + 1):
        for idx in itertools.combinations(range(len(pool)), k):
            R = sp.Matrix.vstack(*[pool[i] for i in idx]) if idx else None
            L = sp.Matrix.vstack(L0, R) if R is not None else L0
            if check_5a(A, C, L) and conditionS_strict(A, C, L):
                return k
    return None
```

**这一层的定位**：**它是证伪工具，不是证明工具。**
价值在于：**在写完整证明之前，先用随机/穷举去找反例。** 命题若有问题，这一层通常几小时内就能找到反例。

**⚠️ 单位陷阱（本文作者亲自踩过）**——"最小行数"有两个不同的计数口径，混用会让整个实验静默失效：

| 量 | 口径 | 正确的对照 |
|---|---|---|
| `q₀ = Σηⱼ` | **总**行数（含 `L₀` 的 `r` 行） | `L0.rows + k == q₀` |
| `dim Z − dim V` | **额外**行数（只有 `R` 的行） | `k == dim Z − dim V` |
| 两者关系 | `dim Z − dim V = q₀ − r = Σ(ηⱼ−1)` | — |

写附录 B 的 `--closedform` 时我把 `L0.rows + k` 拿去比 `dim Z − dim V`，
结果**所有实例都被判成"不匹配"**（而脚本不报错，只是"没有反例也没有匹配"）。
**这类错误是最危险的一种：它让验证静默地什么也没验。**
→ 防御手段：在预期的通过样本上确认**至少有一个 `match`**；
若 `match` 与 `falsified` 都是 0，几乎一定是你自己的口径或筛选逻辑错了。

**本文的两个真实成果都出自这一层**：

- **案例 0**：(S) ⇏ (A)（62/1500）；
- **案例 4**：04 定理 2 的闭式缺前提 `rank[L₀; C] = p + r`——见 §7.3 的完整记录。

**特别推荐的两个实验**：

1. **拟阵检验**（若命题为真，这里通常能找到硬度直觉；若可行族是拟阵，则命题**为假**）：
   检验"可行增广的集合族"是否构成拟阵。**注意 04 §4 已经指出：不要声称这是 matroid 最小基问题**
   （matroid 的任意两个基大小相同，没有优化内容——但**检验它**仍是一个有价值的证伪动作）。
2. **前提审计**：对每个随机实例检查 P1 的全部前提（`rank C = p`、`rank L₀ = r`、`rank[L₀;C] = p+r`、
   功能可观性），然后**只在满足前提的实例上**检验你的公式。**很多"反例"其实是前提被违反**（案例 4 就是这样）。

| | |
|---|---|
| **能发现的错误** | 命题**作为陈述就是错的**（最有价值）；前提被违反的实例；闭式/公式的过估或低估；归约的"⇒ 方向"崩掉 |
| **不能发现的错误** | 大 `n` 才出现的现象；**复杂度结论**——特别注意：**穷举本身是指数的，用穷举"验证 NP-hard"是范畴错误**；实现的系统性偏差（例如所有测试实例都恰好满足某个隐含假设——**所以要主动去违反前提看会发生什么**） |

### 层级 3：SMT / 计算机代数

**先说结论**：**Z3 不擅长秩条件和多项式恒等式。**

- Z3 的核心是 SAT + 理论求解（线性算术、位向量、数组、未解释函数）。
- "矩阵的秩 ≤ k" 是**非线性**的（最好写成"所有 (k+1)×(k+1) 子式全为零"），在实数/复数上是多项式方程组；
  Z3 对非线性实数算术（nlsat）能力有限，**而且很容易返回 `unknown`**。
- "对所有 `λ` 成立"是全称量化——Z3 只能处理**有界**量词，**不能证 `∀λ ∈ ℂ`**。

**所以 Z3 在本问题里能干的是两件有限但有价值的事**：

**(1) 编码"有限域上的组合选择 + 秩条件"，在小实例上验证归约的"⇒ 方向"。**

思路：布尔变量 `b_j` 表示"是否选择第 j 个候选行"；约束 `Σ b_j ≤ k`；
"秩条件"用**存在非零子式**来写（每个候选的 `h×h` 子式引入选择变量，用 `GF(p)` 上的行列式展开写多项式约束）。
于是"SMT 返回 `unsat`"= "**不存在** ≤ k 行的可行增广"（在该**具体实例**上）。

**(2) 用 SAT / 伪布尔求解器做同类事。** 组合选择部分其实是纯 SAT/伪布尔问题，`pysat`、`OR-Tools` 效率更高。
但同样只对**具体小实例**有效。

**计算机代数（sympy / Singular / Macaulay2）** 才是本问题真正的"符号"武器：

| 目标 | 工具 | 说明 |
|---|---|---|
| `(5a)` 精确检验 | `sympy.Matrix.rank()`（有理数域） | 精确；建议用"所有子式"或 Smith 形交叉验证 |
| `P(λ)` 的 generic 秩 | `sympy.matrices.normalforms.smith_normal_form(P, domain=QQ[lam])` | 数非零不变因子。**必要但远不充分**（它只给"一般位置"的秩；(S) 要求**处处**等于 h） |
| `(S)` 的判定 | 手写"子式 → `Poly` → gcd"，**两个方向都查** | 对应 P1 Theorem 4/5；见 §4 层级 1 的技术要点 (3) |
| 根的位置（右半平面版） | `sympy.nroots` 高精度 / `Poly.count_roots` / Routh–Hurwitz | 注意数值精度 |
| 理想成员判定（备用） | `sympy.groebner`、`resultant` | 当条件能写成多项式理想时可用 |

| | |
|---|---|
| **能发现的错误** | 归约"⇒ 方向"在小实例上的编码错误；闭式/判据的笔误；**前提相关**的具体反例 |
| **不能发现的错误** | 符号 `λ` 的全称命题；一般 `n`；复杂度结论；**算法本身的正确性** |

## 5. 针对本问题的具体建议：该形式化什么、不该形式化什么

### 5.1 值得形式化（按性价比从高到低）

**① `(5a) ⇔ row(LA) ⊆ row(L, C, CA)`（04 的引理 1）**（★★★ 最高性价比）

- 纯有限维线性代数，Mathlib 的强项。
- 04 给的证明骨架：`rank[X; W] = rank W + rank(X·Π_{W^⊥})`，取 `X = LA`、`W = row(L,C,CA)`。
- **附带收益**：形式化它逼你把 (5a) 的块顺序、行数、`rank` 的目标写清楚——**而这正是案例 0 的症结。**
- 注意：Lean 里用 `Submodule` 路线，不要走投影矩阵 `Π_{W^⊥}`（那需要正交性、内积结构，
  Mathlib 里有 `Submodule.orthogonal` 但会引入不必要的内积假设）。**用"秩 + 包含"的直接论证更省力。**

**② `k_min = 0 ⟺ row(L₀A) ⊆ row(L₀, C, CA)`，以及闭式 `k ≤ dim Z − dim V` 的上界方向**（★★★）

- 上界方向是**构造性**的：取 `R` 的行 = `V` 在 `Z` 中的一个补基。Lean 里可以真的**构造出这个 `R`**
  （用 `Submodule.exists_isCompl` 一类引理），然后验证 (5a)。这类"构造 + 验证"在 Lean 里非常自然。
- **下界方向需要前提 `rank[L₀; C] = p + r`**（案例 4）。**把前提写在定理陈述里**——
  这本身就是一次有价值的澄清。
- 价值：这是 T1 的主体，也是"仅 (5a) 不可能是 NP-hard"的机器检查依据。

**③ (A) 与 (S) 互不蕴含（两个方向的机器检查反例）**（★★★）

- 形式化的形式是**存在性命题**：`∃ A C L, (A) ∧ ¬(S)` 与 `∃ A C L, (S) ∧ ¬(A)`。
- 证明方式是**给出显式矩阵 + 计算**（Lean 里可以对有限矩阵做 `decide` / `native_decide`，
  或者用具体的有理数矩阵 + `norm_num`）。
- **价值极高**：它回答的正是 CLAUDE.md §5 的第一条 checklist，而且**推翻了一个看似显然的直觉**。
- 注意：`∀λ ∈ ℂ` 不能用 `decide`。对 `¬(S)` 要用**存在量词**：`∃ λ, rank P(λ) ≠ h`——
  给出一个具体的 `λ`（比如见证 2 里的 `λ = 1`）就完成了证明。**这是把"∀"的否定写成"∃"的技巧，
  也是形式化的一个实用模式。**

**④ 归约构造的规模是多项式的（T3 用）**（★★☆）

- 纯 `Nat` 算术：证明 `size(φ(I)) ≤ poly(size(I))`。Lean 里写这个很轻松（`omega`、`nlinarith`）。
- **便宜且必要**，而且恰好是最容易被审稿人抓的一条。

**⑤ `(S) ⇔ gcd(Δ₁,…,Δ_N) = 常数`**（★☆☆，可选）

- 需要多项式代数 + 子式。Mathlib 有 `Polynomial ℂ`、`gcd`、`IsAlgClosed ℂ`，
  但"无公零点 ⇔ 有非常数公因式"和"秩 = 最大非零子式阶数"**可能要自己证**（§2.5 第 9~11 行）。
- 建议：**先只形式化一个方向**，或者干脆先跳过。

### 5.2 不值得形式化

| 不做的对象 | 理由 |
|---|---|
| **完整复杂度理论**（图灵机 + 编码 + 多项式时间 + 归约 + NP） | §3.2：这是另一个课题，占 85% 工作量。**用 `axiom` 引用 Karp 1972** |
| **∃ℝ / 半代数几何** | §3.5：**今天没有可用的形式化基础设施**，而且如果靶子是 ∃ℝ，你要先说服自己"NP-hard"是对的词 |
| **多项式矩阵秩的完整代数理论**（Smith 标准形、PID 上有限生成模的结构定理） | 与本问题的数学核心无关；若要，优先考虑换到 Isabelle/AFP |
| **经典文献定理**（Darouach、Luenberger、Karp 1972、Fernando–Trinh–Jennings 2010、S20） | 引用即可。形式化它们是"给别人重做作业" |
| **数值算法的正确性**（SVD 求秩、浮点误差界） | 层级 1 的脚本只是**启发式工具** |
| **P3 里繁重的构造细节**（Lemma 7 的 `binom(...)` 参数化） | 除非它是你归约的核心机制 |

### 5.3 具体技术提醒（这几条能省你几周）

**① 在 Lean 4 里，"矩阵的秩"请用 `LinearMap.rank` / `Submodule` / `Matrix.rank_eq_finrank_span_row` 表达，
不要走行列式路线。**（这也是案例 3 的教训：行列式路线既笨重、又容易只查一个方向。）

理由：

- 行列式路线要求方阵；而 (5a)(5b) 里的矩阵是**长条状**的，你得先写"取子矩阵"。
- "秩 = 最大非零子式阶数"这条经典定理在 Mathlib 里**未必现成**，
  你要自己写 `Finset.sup` / `Finset.max'` 遍历所有子式——非常笨重。
- 子空间路线是 Mathlib 的主干：
  ```lean
  rowSpace M := Submodule.span R (Set.range fun i => M i)
  M.rank = finrank R (rowSpace M)            -- Matrix.rank_eq_finrank_span_row
  rowSpace M ≤ rowSpace N → M.rank ≤ N.rank  -- Submodule.finrank_mono
  ```
- **例外**：当你要证明 `(S)`（`∀λ` 的秩等式）时，**免不了要谈子式**（因为 gcd 判据就是关于子式的）。
  此时建议**把子式部分隔离成一个独立的引理**，主体论证仍走子空间路线。

**② 用 ℂ，不要用 ℝ，作为基底域。**

- `ℂ` 是代数闭的（Mathlib 有 `IsAlgClosed ℂ`），(5b) 的 `λ ∈ ℂ` 与 gcd/根的论证更自然；
- `Polynomial ℂ` 是欧几里得整环，`gcd` 现成；
- 在 ℝ 上你要额外处理"只有实根才算"这种麻烦。

**③ `∀ λ : ℂ, ...` 是真正的全称量化，不要试图 `decide` / `native_decide`。**
`decide` 只能处理**有限可判定**的命题。正确路径有两条：
(a) 给出 `∀` 证明；(b) 证明它与一个多项式 gcd 条件等价，再对 gcd 做具体计算。
**要证否命题时，把 `¬∀λ` 改写成 `∃λ`，然后给出具体的 `λ`**（§5.1③）。

**④ 区分 `∀λ ∈ ℂ` 与 `∀λ, ℜ(λ) ≥ 0`，并把它们定义成两个不同的命题。**

```lean
def ConditionS_complex : Prop := ∀ λ : ℂ, ...
def ConditionS_rhp     : Prop := ∀ λ : ℂ, 0 ≤ λ.re → ...
```

`ConditionS_complex → ConditionS_rhp` 平凡成立（限制量词域），**反过来不成立**。这两句话本身也值得形式化。

**⑤ "最小行数"用 `IsLeast` 或 `Nat.find` 表达，注意后者的前提。**

```lean
def MinAugRows (k : ℕ) : Prop :=
  (∃ R, Feasible R ∧ R.card = k) ∧ (∀ R, Feasible R → k ≤ R.card)
```

**⑥ 别忘了把"行数"和"秩"分开写。** 观测器阶数是 `rows(L)`（= 指标类型的 `Fintype.card`），不是 `rank L`。
P3 与 P1 的用词不同（§1.1 案例 7）——**在形式化里这是两个不同的表达式。**

**⑦ 把前提写成定理的显式参数。** 案例 4 的教训：不要写成

```lean
theorem kmin_formula ... : kmin A C L0 = dim Z - dim V := ...
```

而要写成

```lean
theorem kmin_formula ... (hprem : (vstack C L0).rank = p + r) :
    kmin A C L0 = dim Z - dim V := ...
```

这样**任何忘记检查前提的引用都会被编译器拦下**。这是形式化最"物有所值"的一种用法。

```lean
/-! ## 0. 基本约定

用 `Fin n` 作指标类型，`Fintype` / `DecidableEq` 实例自动可得。
所有矩阵在 `ℂ` 上——理由见 §5.3②。
-/

variable {n p r : ℕ}

/-- 行拼接：把两个行块摞起来。`Fin.append` 正是我们要的索引合并。
    （Mathlib 里也可能有 `Matrix.fromRows`；用 `#check Matrix.fromRows` 确认。） -/
def vstack {m k n : ℕ} (M : Matrix (Fin m) (Fin n) ℂ) (N : Matrix (Fin k) (Fin n) ℂ) :
    Matrix (Fin (m + k)) (Fin n) ℂ :=
  fun i j => Fin.append (fun a => M a j) (fun b => N b j) i

/-- 行空间：由 `M` 的各行张成的子空间。
    Mathlib 里也可能已叫 `Matrix.rowSpace`；请自行检索确认。 -/
noncomputable def rowSpace {m n : ℕ} (M : Matrix (Fin m) (Fin n) ℂ) :
    Submodule ℂ (Fin n → ℂ) :=
  Submodule.span ℂ (Set.range fun i : Fin m => M i)

/-! ## 1. 条件 (A) 与 (S)——**修正后的 4 块形式**

   (5a)  ≡  rank [L*A ; L ; C*A ; C] = rank [L ; C*A ; C]     （4 块！）
   (S)   ≡  ∀ λ, rank [λ•L - L*A ; C*A ; C] = rank [L ; C*A ; C]
-/

/-- 条件 (A)：**(5a) 的修正形式（左端 4 块）**。 -/
def ConditionA (A : Matrix (Fin n) (Fin n) ℂ)
    (C : Matrix (Fin p) (Fin n) ℂ) (L : Matrix (Fin r) (Fin n) ℂ) : Prop :=
  (vstack (L * A) (vstack L (vstack (C * A) C))).rank
    = (vstack L (vstack (C * A) C)).rank

/-- 条件 (S)，`λ ∈ ℂ` 的强版本。 -/
def ConditionS_complex (A : Matrix (Fin n) (Fin n) ℂ)
    (C : Matrix (Fin p) (Fin n) ℂ) (L : Matrix (Fin r) (Fin n) ℂ) : Prop :=
  ∀ λ : ℂ,
    (vstack (λ • L - L * A) (vstack (C * A) C)).rank
      = (vstack L (vstack (C * A) C)).rank

/-- P3 的右半平面版本。**与上面的强版本不等价**（§5.3④）。 -/
def ConditionS_rhp (A : Matrix (Fin n) (Fin n) ℂ)
    (C : Matrix (Fin p) (Fin n) ℂ) (L : Matrix (Fin r) (Fin n) ℂ) : Prop :=
  ∀ λ : ℂ, 0 ≤ λ.re →
    (vstack (λ • L - L * A) (vstack (C * A) C)).rank
      = (vstack L (vstack (C * A) C)).rank

/-! ## 2. 核心引理①：(A) ⇔ 行空间包含

   直观：把 `LA` 摞到 `[L; CA; C]` 上，秩是否变大，
   完全取决于 `row(LA)` 是否落在 `row(L, CA, C)` 里。
-/

/-- **(A) 等价于 `row(L*A) ⊆ row([L; C*A; C])`**（04 的引理 1；§5.1①）。
    这是最值得形式化的一条。

    证明思路：
      · ←：若 `row(LA) ≤ row(W)`，则 `row([LA; W]) = row(W)`，两边取 `finrank`。
      · →：若秩相等，把 `LA` 的每一行看作 `[LA; W]` 的行，由秩不变推出包含。
    需要的零件：`Submodule.span_le`、`Submodule.finrank_mono`、
    `Matrix.rank_eq_finrank_span_row`。**这条等价本身 Mathlib 里大概没有，要自己证**，
    但零件都在。

    注：04 的证明用了正交投影 `Π_{W^⊥}`；在 Lean 里改用"秩 + 包含"的直接论证更省力
    （避免引入内积结构，见 §5.1①）。 -/
theorem conditionA_iff_rowSpace_le (A : Matrix (Fin n) (Fin n) ℂ)
    (C : Matrix (Fin p) (Fin n) ℂ) (L : Matrix (Fin r) (Fin n) ℂ) :
    ConditionA A C L ↔ rowSpace (L * A) ≤ rowSpace (vstack L (vstack (C * A) C)) := by
  sorry

/-! ## 3. 核心引理②：(A) 与 (S) **互不蕴含**

   这是对 CLAUDE.md §5 第一条 checklist 的机器检查回答。
   两个命题都是**存在性**的：给出显式矩阵即可。
   预期做法：把 §4 层级 1 脚本找到的见证（有理数矩阵）抄进来，
   然后 `decide` / `native_decide` 掉有限的计算部分。

/-- **(S) 不蕴含 (A)**（§1.1 案例 0；实测 62/1500）。
    见证（4 维，h = 3）：
      A = [[-1,-2,-1,1],[1,0,0,0],[1,2,1,0],[2,-2,-2,1]]
      C = [[-1,1,-2,1]]
      L = [[2,1,0,-2]]
    此时 rank[λL-LA;CA;C] = 3 对所有 λ, 但 rank[LA;L;CA;C] = 4 > 3。 -/

    ∃ (n p r : ℕ) (A : Matrix (Fin n) (Fin n) ℂ) (C : Matrix (Fin p) (Fin n) ℂ)
      (L : Matrix (Fin r) (Fin n) ℂ),
      ConditionS_complex A C L ∧ ¬ ConditionA A C L := by
  sorry

/-- **(A) 不蕴含 (S)**（实测 250/1500）。
    见证（3 维，h = 3）：
      A = [[1,1,2],[-2,1,-2],[2,-1,1]]
      C = [[2,-2,-2]]

theorem conditionA_not_implies_conditionS :
    ∃ (n p r : ℕ) (A : Matrix (Fin n) (Fin n) ℂ) (C : Matrix (Fin p) (Fin n) ℂ)
      (L : Matrix (Fin r) (Fin n) ℂ),

/-! ## 4. 核心引理③：`Z`、`V` 与仅 (5a) 下的最小行数（T1 主体）

   04 定理 2 的对象：
     Z := row(O_{L0}) + row(O_C)   （含 row(L0)+row(C) 的最小 A-不变子空间）
     V := row(L0) + row(C) + row(CA)
     k  = dim Z - dim V
   ⚠️ **这个等式需要前提 `rank[L0; C] = p + r`**（04 定理 2 未写出，按字面为假——见 §7.3 与附录 C）。
-/

/-- "有界可观测性矩阵"：把 `M, MA, ..., MA^(n-1)` 摞起来。 -/
def obsMatrix {m n : ℕ} (M : Matrix (Fin m) (Fin n) ℂ) (A : Matrix (Fin n) (Fin n) ℂ) :
    Matrix (Fin (m * n)) (Fin n) ℂ :=
  fun i j => (M * (A ^ (i : ℕ / m))) i j
  -- 说明：真实的索引运算要用 `Fin.divNat` / `Fin.modNat` 之类；这里只示意"按幂次摞行块"。

/-- 能达行空间 `Z`（含 `row(L0) + row(C)` 的最小 `A`-不变子空间）。 -/
noncomputable def Zspace (A : Matrix (Fin n) (Fin n) ℂ) (C : Matrix (Fin p) (Fin n) ℂ)
    (L0 : Matrix (Fin r) (Fin n) ℂ) : Submodule ℂ (Fin n → ℂ) :=
  rowSpace (vstack (obsMatrix L0 A) (obsMatrix C A))
  -- 说明：`obsMatrix` 的行数是 m*n，`vstack` 要求两边行数可加，实际写时要用 `Fin (m*n + p*n)`。

/-- `V := row(L0) + row(C) + row(CA)`。 -/
noncomputable def Vspace (A : Matrix (Fin n) (Fin n) ℂ) (C : Matrix (Fin p) (Fin n) ℂ)
    (L0 : Matrix (Fin r) (Fin n) ℂ) : Submodule ℂ (Fin n → ℂ) :=
  rowSpace (vstack L0 (vstack C (C * A)))

/-- **上界方向**（构造性，最容易形式化的一条）：
    取 `R` 的行 = `V` 在 `Z` 中的一个补基，则 `(A)` 成立且 `rows(R) = dim Z - dim V`。
    Lean 里用 `Submodule.exists_isCompl` 之类的引理取出补空间，再验证 (A)。 -/
theorem conditionA_upper_bound (A : Matrix (Fin n) (Fin n) ℂ)
    (C : Matrix (Fin p) (Fin n) ℂ) (L0 : Matrix (Fin r) (Fin n) ℂ)
    (hZ : Zspace A C L0 ⊔ Vspace A C L0 = ⊤) :   -- 前提略写，仅示意
    ∃ (k : ℕ) (R : Matrix (Fin k) (Fin n) ℂ),
      ConditionA A C (vstack L0 R) := by
  sorry

/-- **`k_min = 0` 的刻画**（04 的第四步前半句；实测 600/600 一致）。
    ⚠️ 04 后半句 `⟺ Z = V` 是**假的**（反例见 §7.3）；不要把那个方向写进定理。 -/
theorem no_augmentation_iff (A : Matrix (Fin n) (Fin n) ℂ)
    (C : Matrix (Fin p) (Fin n) ℂ) (L0 : Matrix (Fin r) (Fin n) ℂ) :
    ConditionA A C L0 ↔ rowSpace (L0 * A) ≤ Vspace A C L0 := by
  sorry

/-! ## 5. "最少行数"这个优化问题的陈述

   注意用"行数"（`Fin k` 的 `k`）而**不是** `rank`——见 §1.1 案例 7 与 §5.3⑥。
-/

/-- 把一个 `k` 行的块 `R` 拼到 `L₀` 下面。 -/
def augment (L₀ : Matrix (Fin r) (Fin n) ℂ) {k : ℕ}
    (R : Fin k → (Fin n → ℂ)) : Matrix (Fin (r + k)) (Fin n) ℂ :=
  fun i j => Fin.append (fun a => L₀ a j) (fun b => R b j) i

/-- 可行增广：增广行都属于候选族 `cand`，且 `(A)` 与 `(S)` 同时成立。
    `cand` 用 `Set` 就够（有限性不是本质的）；T3 里 `cand` 是**有限**候选族。 -/
def Feasible (A : Matrix (Fin n) (Fin n) ℂ) (C : Matrix (Fin p) (Fin n) ℂ)
    (L₀ : Matrix (Fin r) (Fin n) ℂ) (cand : Set (Fin n → ℂ))
    {k : ℕ} (R : Fin k → (Fin n → ℂ)) : Prop :=
  (∀ i, R i ∈ cand)
    ∧ ConditionA A C (augment L₀ R)
    ∧ ConditionS_complex A C (augment L₀ R)

/-- **"最小行数"的精确陈述**：`k` 是最小的可行增广行数。
    用 `IsLeast` 风格直接写，避免 `Nat.find` 的存在性/可判定性前提（§5.3⑤）。 -/
def MinAugRows (A : Matrix (Fin n) (Fin n) ℂ) (C : Matrix (Fin p) (Fin n) ℂ)
    (L₀ : Matrix (Fin r) (Fin n) ℂ) (cand : Set (Fin n → ℂ)) (k : ℕ) : Prop :=
  (∃ R : Fin k → (Fin n → ℂ), Feasible A C L₀ cand R)
    ∧ (∀ (k' : ℕ) (R : Fin k' → (Fin n → ℂ)), Feasible A C L₀ cand R → k ≤ k')

/-! ## 6. 归约骨架（T3；对应 §3.4 的"只形式化数学核心"） -/

/-- Set Cover 的判定实例（示意）。 -/
structure SetCoverInstance where
  U : Finset ℕ            -- 全集
  S : Finset (Finset ℕ)   -- 集合族
  k : ℕ                   -- 预算

/-- "存在大小 ≤ k 的覆盖"。 -/
def HasCover (I : SetCoverInstance) : Prop :=
  ∃ T : Finset (Finset ℕ), T ⊆ I.S ∧ T.card ≤ I.k ∧ I.U ⊆ T.biUnion id

/-- 本问题的**实例**：系统数据 + **有限候选增广行族** + 预算。
    `cand` 必须是显式给出的有限族——这正是 04 §3.4 命题 𝒫′ 的关键，
    也是把困难**从连续参数 `Θ` 转移到离散选择**的关键（否则落到 ∃ℝ，见 §3.5）。 -/
structure SystemInstance where
  n : ℕ
  p : ℕ
  r : ℕ
  A : Matrix (Fin n) (Fin n) ℂ
  C : Matrix (Fin p) (Fin n) ℂ
  L₀ : Matrix (Fin r) (Fin n) ℂ
  cand : Finset (Fin n → ℂ)
  k : ℕ

/-- 本问题的**决策版**："存在行数 ≤ k 的可行增广"。
    （优化问题本身不在 NP 里；必须先有决策版才能谈 NP-完全。） -/
def SystemAccepts (I : SystemInstance) : Prop :=
  ∃ R : Fin I.k → (Fin I.n → ℂ), Feasible I.A I.C I.L₀ (↑I.cand) R

/-- 归约函数 `φ`。**它的具体构造是本证明的数学内容。** -/
variable (φ : SetCoverInstance → SystemInstance)

/-- **核心引理（双向正确性）**：这是真正需要形式化的数学。
    建议拆成两条独立的引理（各自对应 CLAUDE.md §4 的"⇐ 方向"与"⇒ 方向"）。 -/
theorem reduction_iff (I : SetCoverInstance) :
    HasCover I ↔ SystemAccepts (φ I) := by
  sorry

/-- **规模是多项式的**：纯 `Nat` 算术，`omega` / `nlinarith` 大概率够用。
    写具体陈述时，矩阵元素的"位长"也要计（若用 0/1 整数矩阵，就是 O(1)）。 -/

/-! ## 7. 把元数学当作显式假设（§3.4）

   这里用 `axiom` 而**不是** `sorry`：
     · `axiom` 是"我声明这条成立"，定理变成**条件性**的，但**诚实**；
     · `sorry` 是"这里有个洞"，定理是**假的**。
   交付前用 `#print axioms ourProblem_npHard` 自查。
-/

variable (DecisionProblem : Type) (NPHard : DecisionProblem → Prop)
variable (SetCoverDecision OurProblemDecision : DecisionProblem)

/-- 外部文献结果：Set Cover 的判定版是 NP-hard（Karp 1972）。 -/
axiom setCover_npHard : NPHard SetCoverDecision

/-- 从"归约存在"推出 NP-hard（这一步也需要元数学层的一个引理）。 -/
variable (nphard_of_reduction :
  NPHard SetCoverDecision → (∀ I, HasCover I ↔ SystemAccepts (φ I)) → NPHard OurProblemDecision)

/-- **结论**：命题 𝒫′ 是 NP-hard——**在 `setCover_npHard` 这条假设下**。 -/
```

## 7. 其他验证手段

工具之外还有四种"人肉"手段，成本低、收益高，**不要跳过**。

### 7.1 同行评审式对抗审查

**做法**：找一个人（同学、师兄），给他 **30~60 分钟**，任务只有一个：
"请试着构造一个反例推翻这句话"。明确告诉他**不要**做"帮忙改错别字"或"夸两句"这种事。

**为什么有效**：作者对自己证明的盲区是系统性的——你会自动跳过你**以为自己**写过的那一步。
独立读者不会。**本文的案例 0 就是这样一个错误**：作者（我）在"读法"上错了，而推理本身无懈可击。

**给审查者的"攻击清单"**（直接抄给他）：

```text
请按顺序攻击以下几点，每一点都试图给出具体反例：
1. (5a) 的行块：左端到底是 3 块还是 4 块？证明里用的是哪一版？两版不等价。
2. 量词：证明里 "存在 R" 和 "对所有 λ" 的先后顺序是什么？交换后命题还成立吗？
3. (S) 与 (A) 的关系：作者是否假设了其中一个蕴含另一个？给出反例（两者都不蕴含对方）。
4. λ = 0：它能推出什么？是不是只有 rank[LA;CA;C] = h，而非 (A)？
5. 前提审计：列出证明用到的每一条前提
   （rank C = p、rank L0 = r、**rank[L0;C] = p+r**、row(L0) ⊆ row(L)、功能可观性…），
   逐条检查归约构造出的实例是否满足。**特别注意 rank[L0;C] = p+r。**
6. (S) 的检查是否只做了一个方向？是否漏了 "(h+1)×(h+1) 子式恒零"？
7. 右半平面版：如果 (5b) 限制在 ℜ(s) ≥ 0，gcd 判据还对吗？
8. 归约方向：确认是 "Set Cover → 本问题" 而不是反过来。
9. 归约规模：φ 输出的矩阵有多大？元素有多大（多少个二进制位）？还是多项式的吗？
10. 复杂度类：困难是由**离散选择**带来的，还是由**连续参数**带来的？后者意味着 ∃ℝ 而不是 NP-hard。
11. 行数 vs 秩：优化的是 rows(L) 还是 rank L？q0 = Σηj 在哪一个下成立？
12. 退化情形：k = 0、h = 0、L 的行线性相关、"无可行 R" 时命题怎么陈述？
13. 平凡性：是否存在更简单的多项式算法（贪心？匹配？线性规划+舍入？可行族是不是拟阵？）
    能解这个"最小行数"问题，从而命题为假？
```

### 7.3 "证伪优先"策略

**原则**：在花两周写形式化之前，先花**半天**试着**推翻**自己的命题。**本文就是这个策略的产物。**

#### 实战记录：用"证伪优先"在 04 的定理 2 里找到一个缺前提的反例

**步骤 1 — 构造独立实现。** 用 sympy 重写 04 定理 2 的对象（`Z`、`V`、闭式 `k = dim Z − dim V`），
以及穷举最小行数（在候选池上枚举子集，用 4 块 (5a) 判定）。

**步骤 2 — 对照。** 400 个随机实例（n ∈ [3,5]）中 **397 个一致、3 个被证伪**：

```
FALSIFIED: found fewer rows than formula
A = [[-1,-1,-2],[-2,-1,0],[-1,-2,0]]   C = [[1,0,0]]   L0 = [[1,0,0]]
公式 = 1   穷举 = 0     dimZ = 3   dimV = 2
```

**步骤 3 — 手验反例。** 这个实例**极小，可以完全手算**：

- `C = L₀ = [1,0,0]`（要估计的量测就直接测到了！）；
- `CA = C·A = [-1,-1,-2]`（`A` 的第一行），而 `L₀A = C·A`；
- **(5a)**：`rank[LA; L; CA; C] = rank[[-1,-1,-2],[1,0,0],[-1,-1,-2],[1,0,0]] = 2`，
  `rank[L; CA; C] = 2`。**成立。**
- **(5b)**：`P(s) = [sL − LA; CA; C] = [[s+1, 1, 2],[-1,-1,-2],[1,0,0]]`。
  三阶行列式 **恒等于 0**（可直接展开验证），而二阶子式 `det[[-1,-1],[1,0]] = 1 ≠ 0`，
  故 `rank P(s) ≡ 2 = h`。**成立。**
- 所以 `k_min = 0`，但公式给 **1**。

**步骤 4 — 定位根因（这一步最关键）。** 不是"公式完全错"，而是**缺前提**：
该实例的 `rank[L₀; C] = 1 < 2 = p + r`，**违反了 P1 §II 的全行秩假设**。
而 04 的定理 2 陈述里**没有写这个前提**。

**对照实验（决定性）**：

| 实验 | 结果 |
|---|---|
| **加前提过滤**（`rank[L₀;C] = p+r`）后，闭式 vs 穷举 | **0 反例**：`--closedform` 138/138；另一套（候选池限定在 `Z` 内、更严格）369/369 |
| **不加前提**，闭式 vs 穷举 | 397 / 400 一致，**3 个被证伪**（另一轮 150 例中，12 个"违反前提"的实例里有 1 例被证伪，正是下面那个最小反例） |
| 前提满足 / 违反的分布（1500 个随机实例） | 满足 1339，违反 161 |
| `k_min = 0 ⟺ row(L₀A) ⊆ V`（与前提无关的正确刻画） | **600 / 600 一致** |

**结论与建议动作**：

1. **04 定理 2 需要显式写出前提 `rank[L₀; C] = p + r`**（CLAUDE.md §5 本来就把这条列为必须满足）。
   加上前提后，两轮样本（138/138 与 369/369）均与穷举一致，公式站得住。
2. **04「第四步」的 `k^min = 0 ⟺ Z = V` 是错的**：上述反例 `k^min = 0` 但 `Z ≠ V`。
   正确刻画只有前半句 `k^min = 0 ⟺ row(L₀A) ⊆ V`（实测 600/600）。
3. **04 定理 2 的证明第二步也有瑕疵**：`Z ⊆ W + V (∗)` 在上面的反例里**不成立**
   （`W + V = V` 只有 2 维，而 `Z` 是 3 维）。
   `(A)` 只说 `row(LA) ⊆ row(L,C,CA)`，**并不自动给出 `Z`（`A`-不变闭包）的包含关系**——
   原文"逐项展开即得"的归纳步对 `row(CA^{q+1})` 不成立。
   建议把这一步改写成用 `dim(W ∩ V) ≥ dim row(L₀) = r`（由前提保证）来抵消 `r`。

> **这一节本身就是"证伪优先"的示范**：总投入约 1 小时（写脚本）+ 10 分钟（手验），
> 结果抓到了一个会影响正式文档的前提缺失。**没有任何证明助手能在同等成本下做到这件事。**

#### 其他"证伪优先"动作清单

1. **随机搜索**：用附录 B 的脚本随机生成几千个 `(A, C, L₀, 候选族)`，
   找"最小行数 < 理论预测"的实例。
2. **极端实例**：`A` 是幂零 Jordan 块（`ηⱼ` 很大）；`C` 只有一行（观测能力极弱）；
   `L₀` 的行彼此高度耦合；**以及主动违反前提**（如 `row(L₀) ⊆ row(C)`，案例 4 的反例就是这样来的）。
3. **平凡算法搜索**：试着找一个**多项式**算法解最小行数问题。**特别是**检查"可行增广的集合族"
   是否构成**拟阵**——若是，贪心就是最优的，**问题就是多项式可解的，NP-hard 命题为假**。
4. **把它当已证定理找漏洞**：问"那个证明最薄弱的环节在哪里"——通常就是你归约里最容易崩的地方。

| **`#print axioms`** | 列出某定理依赖的公理（用于审计是否有洞） |
| **Curry–Howard 对应** | "命题 = 类型，证明 = 程序" |
| **decide / native_decide** | 对**有限可判定**命题用计算直接判定 |
| **Loogle / Moogle** | Lean 社区的引理搜索引擎（按类型 / 按自然语言） |
| **generic rank（一般秩）** | 多项式矩阵在"一般位置"的秩；**不等于**"对所有参数取值都等于该秩" |
| **gcd of maximal minors** | 所有最高阶非零子式的最大公因式；等于常数 ⟺ 秩处处不下降 |
| **many-one / Karp 归约** | 多项式时间可计算的多对一归约；NP-hard 的标准工具 |
| **A-不变子空间** | 满足 `XA ⊆ X` 的子空间；04 定理 2 里的 `Z` 就是"最小的、包含 `row(L₀)+row(C)` 的那个" |
| **∃ℝ（存在性实数理论）** | 判定"多项式系统是否有实解"的复杂度类，介于 NP 与 PSPACE 之间（§3.5） |

```python
#!/usr/bin/env python3
# -*- coding: utf-8 -*-
"""
verify_observer_conditions.py —— 对 04 中可机器检查的断言做独立验证。

用法:
    python verify_observer_conditions.py --demo
    python verify_observer_conditions.py --independence 1500     # (A) 与 (S) 的独立性
    python verify_observer_conditions.py --closedform 400        # 闭式 + 前提对照
    python verify_observer_conditions.py --witnesses             # 打印可直接抄进 Lean 的见证

约定（**修正后的 4 块 (5a)**）:
    (5a)/(A) : rank[L*A ; L ; C*A ; C] == rank[L ; C*A ; C]
    (5b)/(S) : rank[lam*L - L*A ; C*A ; C] == rank[L ; C*A ; C]  对所有 lam in C
               <=> (i) 所有 (h+1)x(h+1) 子式恒为 0
                且 (ii) 所有 hxh 子式的 gcd 是非零常数
                   （**只查 (ii) 是错的**：它只保证 rank >= h）
    闭式     : k = dim Z - dim V，Z = row(O_L0)+row(O_C)（最小 A-不变子空间），
               V = row(L0)+row(C)+row(C*A)
               **需要前提 rank[C;L0] = p+r**（04 定理 2 未写出；见 §7.3）
"""
import argparse
import itertools
import random

import sympy as sp

lam = sp.symbols('lam')


# ------------------------------------------------------------ 基本条件

def check_5a(A, C, L):
    """(5a) 的**修正 4 块**形式：rank[LA; L; CA; C] == rank[L; CA; C]。"""
    A, C, L = map(sp.Matrix, (A, C, L))
    lhs = sp.Matrix.vstack(L * A, L, C * A, C).rank()
    rhs = sp.Matrix.vstack(L, C * A, C).rank()
    return lhs == rhs


def h_of(A, C, L):
    """h := rank[L; C*A; C]。(S) 中被比较的目标秩。"""
    A, C, L = map(sp.Matrix, (A, C, L))
    return sp.Matrix.vstack(L, C * A, C).rank()


def conditionS_strict(A, C, L, cap=20000):
    """严格判定 (S)。返回 (bool 或 None, 说明)。

    必须同时检查两个方向——只查 gcd 会漏掉 rank 超过 h 的情形（本文实测 13/1500）。
    """
    A, C, L = map(sp.Matrix, (A, C, L))
    h = h_of(A, C, L)
    P = sp.Matrix.vstack(lam * L - L * A, C * A, C)
    rows, cols = P.shape

    def minors(k):
        cnt = 0
        for rs in itertools.combinations(range(rows), k):
            for cs in itertools.combinations(range(cols), k):
                cnt += 1
                if cnt > cap:
                    raise RuntimeError("too many minors")
                yield sp.expand(P.extract(rs, cs).det())

    try:
        # (i) rank <= h 处处成立
        if h + 1 <= min(rows, cols):
            for d in minors(h + 1):
                if d != 0:
                    return False, "存在 (h+1)x(h+1) 子式不恒为零 => 某处 rank > h"
        if h == 0:
            ok = all(d == 0 for d in minors(1))
            return ok, "h=0 退化情形"
        # (ii) rank >= h 处处成立
        polys = [sp.Poly(d, lam) for d in minors(h) if d != 0]
        if not polys:
            return False, "所有 hxh 子式恒为零 => rank 处处 < h"
        g = polys[0]
        for m in polys[1:]:
            g = g.gcd(m)
            if g.degree() == 0:
                break
        if g.degree() != 0:
            return False, f"gcd 非常数 ({g}) => 存在 lam 使 rank < h"
        return True, "OK"
    except RuntimeError:
        return None, "too many minors"


# ------------------------------------------------------------ 04 定理 2 的对象

def obs(M, A, n):
    """把 M, M*A, ..., M*A^(n-1) 摞起来（可观测性矩阵）。"""
    blk, cur = [M], M
    for _ in range(n - 1):
        cur = cur * A
        blk.append(cur)
    return sp.Matrix.vstack(*blk)


def dims_ZV(A, C, L0):
    """返回 (dim Z, dim V)。"""
    A, C, L0 = map(sp.Matrix, (A, C, L0))
    n = A.shape[0]
    Z = sp.Matrix.vstack(obs(L0, A, n), obs(C, A, n))
    V = sp.Matrix.vstack(L0, C, C * A)
    Zb = sp.Matrix([list(map(sp.simplify, r)) for r in Z.rowspace()])
    Vb = sp.Matrix([list(map(sp.simplify, r)) for r in V.rowspace()])
    return (Zb.rank() if Zb.rows else 0), (Vb.rank() if Vb.rows else 0)


def premise_full_row_rank(A, C, L0):
    """P1 §II 的前提：rank[C; L0] = p + r。**04 定理 2 漏写的正是这条。**"""
    C, L0 = sp.Matrix(C), sp.Matrix(L0)
    return sp.Matrix.vstack(C, L0).rank() == C.rows + L0.rows


def row_subset(A, C, L0):
    """row(L0*A) ⊆ V = row(L0)+row(C)+row(C*A) ?（k_min = 0 的正确刻画）"""
    A, C, L0 = map(sp.Matrix, (A, C, L0))
    V = sp.Matrix.vstack(L0, C, C * A)
    rV = V.rank()
    LA = L0 * A
    return all(sp.Matrix.vstack(V, LA[i, :]).rank() == rV for i in range(LA.rows))


def min_extra_rows(A, C, L0, pool, maxk, require_S=True):
    """在候选池 pool 里穷举所有大小 <= maxk 的子集，返回最小**额外**行数（无法则 None）。

    【单位警告 —— 极易出错】
      · `q0 = sum(eta_j)`       是**总**行数（含 L0 的 r 行） → 对照 `L0.rows + k == q0`
      · `dim Z - dim V`         是**额外**行数               → 对照 `k == dim Z - dim V`
      · 两者关系：`dim Z - dim V == q0 - r == sum(eta_j - 1)`
    本函数返回的是**额外**行数 `k`。
    **这是指数时间**，只能用于玩具规模。
    """
    A, C, L0 = map(sp.Matrix, (A, C, L0))
    for k in range(maxk + 1):
        for idx in itertools.combinations(range(len(pool)), k):
            rows = [pool[i] for i in idx]
            L = sp.Matrix.vstack(L0, *rows) if rows else L0
            if not check_5a(A, C, L):
                continue
            if require_S:
                okS, _ = conditionS_strict(A, C, L)
                if okS is not True:
                    continue
            return k
    return None


# ------------------------------------------------------------ 实验

def _rand_system(seed, n_lo=2, n_hi=5, span=2):
    r = random.Random(seed)
    n = r.randint(n_lo, n_hi)
    p = r.randint(1, n - 1)
    rr = r.randint(1, n - p)
    A = sp.Matrix([[r.randint(-span, span) for _ in range(n)] for _ in range(n)])
    C = sp.Matrix([[r.randint(-span, span) for _ in range(n)] for _ in range(p)])
    L0 = sp.Matrix([[r.randint(-span, span) for _ in range(n)] for _ in range(rr)])
    return A, C, L0


def exp_independence(trials):
    """实验 A：(A) 与 (S) 是否互相蕴含。（本文实测：都不蕴含。）"""
    st = {"tested": 0, "both": 0, "S_not_A": 0, "A_not_S": 0,
          "neither": 0, "unknown": 0, "rankP_gt_h": 0}
    wit_S_not_A, wit_A_not_S = [], []
    for seed in range(trials):
        A, C, L0 = _rand_system(seed, n_lo=2, n_hi=4)
        okS, why = conditionS_strict(A, C, L0)
        if okS is None:
            st["unknown"] += 1
            continue
        okA = check_5a(A, C, L0)
        st["tested"] += 1
        h = h_of(A, C, L0)
        # 粗查 generic rank（只看 (ii) 会漏的那种情况）：随机几个数值 lam
        for v in (sp.Rational(7, 3), sp.Rational(-11, 5), sp.Integer(0)):
            Pv = sp.Matrix.vstack((lam * L0 - L0 * A).subs(lam, v), C * A, C)
            if Pv.rank() > h:
                st["rankP_gt_h"] += 1
                break
        if okS and okA:
            st["both"] += 1
        elif okS and not okA:
            st["S_not_A"] += 1
            if len(wit_S_not_A) < 1:
                wit_S_not_A.append((A, C, L0))
        elif okA and not okS:
            st["A_not_S"] += 1
            if len(wit_A_not_S) < 1:
                wit_A_not_S.append((A, C, L0, why))
        else:
            st["neither"] += 1
    print("实验 A（(A) 与 (S) 的独立性）:", st)
    for A, C, L0 in wit_S_not_A:
        print("  [S 成立 / A 失败] A =", A.tolist(), "C =", C.tolist(), "L =", L0.tolist())
    for A, C, L0, why in wit_A_not_S:
        print("  [A 成立 / S 失败] A =", A.tolist(), "C =", C.tolist(), "L =", L0.tolist(), "|", why)
    return st


def exp_closedform(trials):
    """实验 B：闭式 k = dim Z - dim V 在**有/无前提**下的表现。"""
    st_with = {"tested": 0, "match": 0, "falsified": 0, "pool_too_poor": 0}
    st_without = {"tested": 0, "match": 0, "falsified": 0, "pool_too_poor": 0}
    bad = []
    for seed in range(trials):
        A, C, L0 = _rand_system(seed, n_lo=3, n_hi=5)
        dZ, dV = dims_ZV(A, C, L0)
        kf = dZ - dV
        # 候选池：随机向量（限制在 Z 的基行里，模拟"聪明的候选族"）
        n = A.shape[0]
        Z = sp.Matrix.vstack(obs(L0, A, n), obs(C, A, n))
        pool = [sp.Matrix([list(map(sp.simplify, r))]) for r in Z.rowspace()]
        r2 = random.Random(999 + seed)
        for _ in range(4):
            v = sp.Matrix([[r2.randint(-2, 2) for _ in range(n)]])
            pool.append(v)
        k = min_extra_rows(A, C, L0, pool, maxk=min(kf, len(pool)), require_S=False)
        if k is None:
            continue
        # 【单位警告】`k` 是**额外**行数，`kf = dim Z - dim V` 也是**额外**行数，
        # 所以两者直接比较。**不要**拿 `L0.rows + k`（总行数）去比 `kf`——
        # 这正是本文正文反复提醒的那类记账错误（写这段脚本时我自己就犯过一次）。
        target = st_with if premise_full_row_rank(A, C, L0) else st_without
        target["tested"] += 1
        if k == kf:
            target["match"] += 1
        elif k < kf:
            target["falsified"] += 1
            if len(bad) < 3:
                bad.append((A, C, L0, kf, k, dZ, dV, premise_full_row_rank(A, C, L0)))
        else:
            target["pool_too_poor"] += 1
    print("实验 B（闭式 vs 穷举）")
    print("  满足前提 rank[C;L0]=p+r :", st_with)
    print("  不满足前提             :", st_without)
    for A, C, L0, kf, k, dZ, dV, prem in bad:
        print("  ---- 被证伪 (前提满足? %s)" % prem)
        print("       A =", A.tolist(), "C =", C.tolist(), "L0 =", L0.tolist())
        print("       公式 k =", kf, " 穷举 k =", k, " dimZ =", dZ, "dimV =", dV)
    return st_with, st_without


def exp_kmin0(trials):
    """实验 C：k_min = 0 <=> row(L0*A) ⊆ V（与前提无关的正确刻画）。"""
    st = {"tested": 0, "agree": 0, "disagree": 0}
    for seed in range(trials):
        A, C, L0 = _rand_system(10000 + seed, n_lo=2, n_hi=5)
        st["tested"] += 1
        if check_5a(A, C, L0) == row_subset(A, C, L0):
            st["agree"] += 1
        else:
            st["disagree"] += 1
    print("实验 C（k_min = 0 的刻画）:", st)
    return st


def show_witnesses():
    """打印可直接抄进 Lean 的见证。"""
    print("=== 见证 1：(S) 成立但 (A) 失败（案例 0） ===")

    C = sp.Matrix([[-1, 1, -2, 1]])
    L = sp.Matrix([[2, 1, 0, -2]])
    print("A =", A.tolist())
    print("C =", C.tolist(), " L =", L.tolist())
    print("h =", h_of(A, C, L))
    print("(S) =", conditionS_strict(A, C, L))
    print("(A) =", check_5a(A, C, L))
    print("rank[L*A; L; C*A; C] =", sp.Matrix.vstack(L * A, L, C * A, C).rank())

    print()
    print("=== 见证 2：(A) 成立但 (S) 失败 ===")
    A = sp.Matrix([[1, 1, 2], [-2, 1, -2], [2, -1, 1]])
    C = sp.Matrix([[2, -2, -2]])
    L = sp.Matrix([[2, 1, 1], [2, -2, 1]])
    print("A =", A.tolist())
    print("C =", C.tolist(), " L =", L.tolist())
    print("h =", h_of(A, C, L))
    print("(A) =", check_5a(A, C, L))

          sp.Matrix.vstack((lam * L - L * A).subs(lam, 1), C * A, C).rank(),

    print()
    print("=== 见证 3：04 定理 2 的闭式缺前提的反例（§7.3） ===")
    A = sp.Matrix([[-1, -1, -2], [-2, -1, 0], [-1, -2, 0]])
```
